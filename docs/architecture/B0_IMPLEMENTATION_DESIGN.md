# ١. Scope

## ما تشمله ب٠

| # | البند |
|---|---|
| ١ | **Bootstrap Wizard** — شاشة تهيئة تعمل مرة واحدة عند أول تشغيل |
| ٢ | **تذكرة الإقلاع** — إصدارها · تبادلها · احتراقها |
| ٣ | **جلسة الإقلاع** — قصيرة العمر، تحمل النموذج بعد احتراق التذكرة |
| ٤ | **جدول حالة النظام** — علم التهيئة وما يلزمه |
| ٥ | **دالة الإقلاع** — بنمط الإقلاع §٧.٢، بمفتاح الخدمة |
| ٦ | **إعادة تصنيف `seed_first_admin`** — أداة طوارئ واستعادة، ويكتسب إصدار تذكرة جديدة |
| ٧ | **مدخلا الجرد الجديدان** — يُضافان قبل الشحن (ق٣) |

## ما لا تشمله

| البند | مكانه |
|---|---|
| **حساب دعم المورّد** | **قرار منفصل غير محسوم** — §١٨.٨ |
| بوابة المورّد (Vendor Portal) | مشروع مستقلّ · ب٠ يخدمها بلا أن يعرفها (أ١١) |
| رفع أصول الشركة إلزامياً | يبقى اختيارياً حتى س٦ |
| تعدّد الشركات في نشرٍ واحد | **خارج المعمارية** — `company_config` صفّ واحد بالتصميم |
| أي تغيير في نموذج الصلاحيات | §٥.٣ قرار مؤجَّل |

# ٢. لماذا تعتمد على س٤ — وهي منفصلة عنها

**التبعية أحادية الاتجاه وتقنية بحتة:**

> قبل س٤، مفتاح النشر العلني يكتب في `company_config` و`company_assets` **مباشرة**. فأيّ حارس نضعه على الـ Wizard **لا يحرس شيئاً** — المهاجم لا يحتاج الـ Wizard أصلاً.
>
> **معنى الحارس نفسه لا يوجد إلا بعد س٤.**

**والاتجاه المعاكس معدوم:** س٤ لا تحتاج ب٠ إطلاقاً — أداة الاستعادة تستعمل مفتاح الخدمة، ومفتاح الخدمة يتجاوز RLS.

**ونتيجة عملية ثانية:** الـ Wizard المكتوب قبل س٤ يُكتب على نموذج بيانات متساهل ثم **يُعاد كتابته** بعدها. مرّتان بدل مرة.

# ٣. Business Impact

| | قبل | بعد |
|---|---|---|
| تثبيت عميل جديد | طرفية + مستودع + مفتاح خدمة + سكربت | **رابط واحد ونموذجان** |
| من يستطيع التثبيت | من يملك مفتاح الخدمة | **من يملك تذكرة صالحة** |
| ما يراه العميل من أسرار | مفتاح الخدمة | **لا شيء** |
| النشر الحالي | — | **لا يتأثّر** — مُهيَّأ سلفاً بأداة الاستعادة |

**تجربة العميل المستهدفة — بلا خطوة إضافية واحدة:**

```
يفتح الرابط  →  بيانات الشركة  →  بيانات المدير  →  إنشاء النظام  →  شاشة الدخول
```

# ٤. Technical Design

## ٤.١ المسار

```
النشر / بوابة المورّد / أداة الاستعادة
        └─► إصدار تذكرة  (مُصدِرٌ واحد · §١٨.٣ خاصية ٦)
                └─► رابط التهيئة

المتصفح  ① قراءة حالة التهيئة   → Wizard أم شاشة دخول
         ② تبادل التذكرة بجلسة إقلاع → التذكرة تحترق
         ③ تنظيف العنوان
         ④ النموذجان → تنفيذ الإقلاع → شاشة الدخول
```

## ٤.٢ الحارس

```
جلسة إقلاع صالحة  +  حالة «غير مُهيَّأ»  +  حدّ محاولات
```

**وسقط «صفر مستخدمين» حارساً** — حالة التهيئة أقوى منه وأدقّ: النظام قد يُهيَّأ ثم يُحذف مستخدم، والحالة لا تكذب.

## ٤.٣ نقل التذكرة

**لا Query String.** التذكرة تُنقل بما لا يصل إلى الخادم ولا إلى روبوتات معاينة الروابط، وتُبادَل بجلسة إقلاع **بمجرد تحميل الصفحة**، ثم يُنظَّف العنوان.

**والطبقات ليست متكافئة، وهذا مقصود:**

| الطبقة | تغلق | لا تغلق |
|---|---|---|
| عدم استعمال Query String | سجلّات الخادم · Analytics · Referer · روبوتات المعاينة | سجلّ متصفّح العميل · لقطة الشاشة |
| **الاحتراق الفوري** | **كل تسرّب لاحق** | تسرّباً في الثواني الأولى |
| تنظيف العنوان | بقاءه في الشريط وسجلّ المتصفح | ما سجّله تطبيق المراسلة قبل الفتح |
| المهلة | رابطاً منسيّاً | شيئاً خلال المهلة |

> **تنظيف العنوان نظافةٌ لا حارس.** الحارس الحقيقي هو الاحتراق الفوري.

## ٤.٤ حالة النظام

جدول مستقلّ ذو صفّ واحد يحمل: **علم التهيئة** · **من ومتى** · **كيف** (بالمورّد أم ذاتياً) · **تجزئة التذكرة ومهلتها وعدّاد محاولاتها** · **نسخة المخطّط**.

**الكتابة لمفتاح الخدمة وحده.** و`anon` لا يقرأ الجدول — بل دالة تُرجع **بوليان واحداً**.

**ولا يُوضع علم التهيئة في `company_config`** — §١٨.٥.

## ٤.٥ الذرّية والتعويض

بحسب §١٨.٦. والنقطة الحاكمة: **علم التهيئة يُكتب آخرَ شيء**، وفشل ما بعد إنشاء حساب GoTrue **يُعوَّض بحذفه** — نفس نمط `user-admin` المُختبَر في س٢.

## ٤.٦ ما يبقى مفتوحاً للتنفيذ — لا للمعمارية

هذه **تُحسم أثناء التنفيذ أو في مراجعة الـ PR**، ولا تُعدّ قرارات معمارية:

مدّة صلاحية التذكرة · مدّة جلسة الإقلاع · أسماء الحقول والجداول · أسماء الملفات والمجلدات · شكل الشاشات وعدد خطواتها · صياغة الرسائل · تفاصيل تنظيف العنوان · حدّ المحاولات الرقميّ.

**وما لا يُفتح للنقاش لأنه معماريّ:** التذكرة لمرة واحدة · مُجزَّأة · بمهلة · لا في Query String · مُصدِرٌ واحد · الإغلاق بحالة لا بإعداد · علم التهيئة آخرَ شيء · الثابت أ١١.

# ٥. Anonymous Access Inventory — الإضافات

بحسب ق٣: **يُضافان قبل الشحن لا بعده.**

| المورد | المبرّر | الآلية | المالك |
|---|---|---|---|
| قراءة حالة التهيئة | الواجهة تقرّر: Wizard أم شاشة دخول | `SECURITY DEFINER` · بوليان واحد | الإقلاع |
| تنفيذ الإقلاع | إنشاء المدير الأول وملفّ الشركة | نمط الإقلاع §٧.٢ | الإقلاع |

**والثاني يُغلق ذاتياً** بعد أول نجاح — المدخل المجهول الوحيد الذي ينتهي بانتهاء غرضه.

# ٦. Risks

| # | الخطر | التخفيف |
|---|---|---|
| **خ١** | **Installer Race** — من يسبق يصير المدير | التذكرة: الحارس الذي يحوّل السؤال من «من وصل أولاً؟» إلى «من يملك سلطة النشر؟» |
| **خ٢** | بقاء باب الإقلاع مفتوحاً بعد التهيئة | الإغلاق **بحالة في القاعدة** لا بإعداد — والإعداد يُنسى ويُعاد |
| **خ٣** | مدير يمسح علم التهيئة سهواً من الإعدادات | العلم في جدول نظام لا في `company_config` |
| **خ٤** | روبوت معاينة الروابط يحرق التذكرة | لا Query String · والتبادل بـJavaScript لا بطلب `GET` |
| **خ٥** | فشل جزئي يترك حساباً بلا ملفّ | التعويض بالحذف · وقابلية الاستئناف ما دام العلم غير مكتوب |
| **خ٦** | تسرّب الرابط بعد أسابيع | الاحتراق الفوري يجعل التسرّب اللاحق بلا قيمة |
| **خ٧** | ضياع التذكرة قبل الإتمام | أداة الاستعادة تُصدر تذكرة جديدة — دورها الجديد المصمَّم |
| **خ٨** | نسختان من منطق إصدار التذكرة (سكربت + بوابة) | **مُصدِرٌ واحد** — نفس مبدأ `authorize()` |

# ٧. Verification Plan

**§٩١–٩٥: الأمن يُثبَت بمحاولة الفعل الممنوع.**

| # | الفحص | المتوقّع |
|---|---|---|
| ١ | تنفيذ الإقلاع **بلا تذكرة** | رفض |
| ٢ | بتذكرة **خاطئة** | رفض |
| ٣ | بتذكرة **منتهية** | رفض |
| ٤ | بتذكرة **مستعملة** (احترقت) | رفض |
| ٥ | **بعد التهيئة** بتذكرة صالحة | رفض — الباب مغلق بالحالة |
| ٦ | قراءة حالة التهيئة بـ`anon` | بوليان واحد · **ولا شيء غيره** |
| ٧ | محاولة قراءة جدول الحالة مباشرة بـ`anon` | رفض |
| ٨ | إقلاع ناجح | مدير يدخل · شركة مهيّأة · العلم مكتوب |
| ٩ | **فشل مُحاكى بعد إنشاء GoTrue** | لا حساب يتيم · العلم غير مكتوب · الاستئناف ممكن |
| ١٠ | محاولات متكرّرة بتذاكر خاطئة | حظر |
| ١١ | تسريب: هل تظهر التذكرة في سجلّات الخادم؟ | **لا** |

**تصريح مسبق:** الفحوص التي تتطلّب طلباً حياً عبر الشبكة **لا تُنفَّذ من بيئة التنفيذ** (محجوبة عن `*.supabase.co`)، وتُسلَّم أوامرها جاهزة — كما في س٣ وس٤.

# ٨. Rollback

| الطبقة | التراجع |
|---|---|
| القاعدة | إسقاط جدول الحالة ودواله — **ولا بيانات عمل تتأثّر** |
| الدالة | إلغاء نشرها |
| الواجهة | `git revert` |

**ونقطة اللاعودة الوحيدة:** نظامٌ هُيّئ فعلاً لا يُعاد إلى «غير مُهيَّأ» إلا بأداة الاستعادة — **وهذا مقصود لا عيب**.

# ٩. تقسيم العمل إلى PRs

| PR | المسؤولية |
|---|---|
| **١** | جدول الحالة · دالة قراءة الحالة · مُصدِر التذكرة |
| **٢** | دالة الإقلاع بنمط §٧.٢ · الذرّية والتعويض |
| **٣** | شاشات الـ Wizard · تبادل التذكرة · التوجيه |
| **٤** | إعادة تصنيف أداة الاستعادة وإكسابها إصدار التذكرة |

**الترتيب مُلزِم:** لا شاشة قبل دالة، ولا دالة قبل حالة.

---

# ١٠. Deployment

**ب٠ لا تُنشر على النشر الحالي بأثر رجعيّ** — فهو مُهيَّأ سلفاً، وحالته ستُضبط على «مُهيَّأ» عند الترحيل. **والـ Wizard لا يظهر له إطلاقاً.**

**وأول استعمال حقيقي لب٠ يكون مع أول عميل جديد.**
