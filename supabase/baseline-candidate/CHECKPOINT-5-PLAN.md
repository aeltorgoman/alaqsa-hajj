# خطّةُ التحوّل المقترحة — نقطة التفتيش ٥

> # ⛔ مسوَّدةٌ فحسب — لا شيء هنا معتمَد
>
> **لا يعتمد هذا المستند أيَّ عملية.** لا `migration repair`، ولا
> تغييرَ حالةٍ إلى `reverted` أو `applied`، ولا أرشفةَ ترحيلات،
> ولا مصالحةَ سجلّ، ولا أيَّ فعلِ تحوّل.
>
> وكلُّ عمليةٍ من هذه يلزمها **قرارٌ معماريٌّ مستقلّ**، بعد
> تحقّقِ الأمرين معاً:
>
> 1. **نقطة ٤ مُثبَتةٌ تماماً** — خطُّ أساسٍ مبنيٌّ ومُقارَنٌ ببناءين.
> 2. **نقطة ١ مغلقةٌ تماماً** — ٤٢ حمولةَ SQL محفوظةٌ بدقّة البايت.
>
> وحتى يتحقّق الأمران، هذا النصُّ **مادّةُ تفكيرٍ لا إذنُ تنفيذ**.

> ⚠️ **اقتراحٌ لا تنفيذ.** لم يُنفَّذ من هذه الخطّة شيء، ولا يُنفَّذ
> منها شيءٌ قبل إذنٍ صريح.

## شروطٌ سابقة — كلُّها لازمةٌ قبل أوّل خطوة

| # | الشرط | الحالة |
|---|---|---|
| ١ | **نقطة ١ مغلقةٌ تماماً**: ٤٢ حمولةَ SQL من السجلّ محفوظةٌ بدقّة البايت ومُتحقَّقٌ منها | ❌ **مفتوحة** |
| ٢ | نقطة ٤ منجَزة: خطُّ أساسٍ مبنيٌّ ومُثبَتُ التكافؤ ببناءين من الصفر | ❌ محجوبةٌ بيئياً |
| ٣ | بيئةٌ فيها شبكةٌ وDocker وبوستجرس ١٧ | ❌ غير متوفّرة هنا |
| ٤ | نسخةٌ احتياطيّةٌ حديثةٌ للمشروع | — |

**ولا تبدأ نقطة ٥ قبل إغلاق نقطة ١.** ليستا مهمّةً واحدة، ولا
تُخلطان: الدليلُ يُحفظ أولاً، ثم يُعاد ترتيبُ ما يشهد عليه.

## التسلسل المقترح

### أ) أرشفةُ التاريخ (المستودع وحده)

تُنقل الترحيلاتُ السبعةُ والثلاثون من `supabase/migrations/` إلى
`supabase/migrations-archive/`. **لا تُحذف ولا تُعاد تسميتُها**:
التاريخُ يُزاح عن المسار الفعّال ويبقى مقروءاً.

### ب) إنشاءُ ملفّ خطّ الأساس بطابعٍ من الـCLI

```bash
npm run supabase -- migration new v1_baseline
```

ثم يُنسخ المرشَّحُ المُثبَت في الملفّ الذي ولّده الـCLI.
**ولا يُخترَع طابعٌ زمنيّ يدوياً** — هذا هو بيتُ الداء الذي نعالجه.

### ج) مصالحةُ السجلّ البعيد — **إصلاحٌ واحدٌ مقصود**

الحالةُ اليوم: **٤٦** صفّاً في السجلّ البعيد مقابل ٣٧ ملفّاً، بإصداراتٍ
متباعدة (آخرُها `20260921141422` مقابل `20260921120000`).

المقترح:

```bash
# كلُّ صفٍّ تاريخيّ يُعلَّم «مُرتجَعاً» فلا يُعاد تشغيله
npm run supabase -- migration repair --status reverted <كلُّ إصدارٍ تاريخيّ>
# وخطُّ الأساس يُعلَّم «مُطبَّقاً» — فهو يصف الحالة القائمة
npm run supabase -- migration repair --status applied <إصدارُ خطّ الأساس>
```

⚠️ **ولا صفَّ يُحذف** من `supabase_migrations.schema_migrations`.
الإصلاحُ يغيّر الحالةَ لا يمحو الشهادة — ولهذا كانت نقطة ١ شرطاً.

### د) إثباتُ الحلقة

```bash
npm run supabase -- migration list    # المستودعُ والبعيدُ متّفقان
npm run supabase -- db push           # يجب ألّا يجد شيئاً ليطبّقه
```

ثم بصمةٌ بعديّةٌ على الحيّ تُقارَن ببصمة ما قبل التحوّل: **يجب
ألّا تتغيّر**. فالتحوّل عمليّةُ دفاترَ لا عمليّةُ مخطَّط.

### هـ) إثباتُ الدورة كاملةً (نقطة ٦)

ترحيلٌ صغيرٌ لا ضرر فيه يمرّ بالمسار الكامل: إنشاءٌ بالـCLI →
تحقّقٌ محلّيّ → PR → دمج → `db push` → تحقّقٌ بعديّ.

## المخاطر والضوابط

| الخطر | الضابط |
|---|---|
| `repair` يُطبَّق على إصدارٍ خاطئ | تُكتب القائمةُ كاملةً وتُراجَع قبل التنفيذ؛ لا حلقاتٌ مولَّدة |
| `db push` يشغّل ترحيلاً غير متوقَّع | يسبقه `migration list` ومراجعةُ المجموعة المقصودة |
| فقدُ شهادةِ السجلّ | نقطة ١ مغلقةٌ أولاً — شرطٌ لا تفاوض فيه |
| خطُّ أساسٍ ناقصٌ أمنياً | برهانُ التكافؤ من المستويين قبل التحوّل |
| تباعدٌ بين ١٦ و١٧ | البناءُ والبرهانُ على بوستجرس ١٧ حصراً |

## ما **لا** تفعله نقطة ٥

لا تغيّر مخطَّطاً · لا تحذف صفَّ سجلّ · لا تمسّ بيانات عمل ·
لا تعدّل شيفرةَ التطبيق · لا تُصلح ديناً تقنياً عارضاً.
